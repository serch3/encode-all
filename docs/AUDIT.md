# App audit — October 13, 2026

The app has a solid queue model and shares command generation between the main process and renderer. The main weaknesses were setup readiness, desktop executable discovery, encoder-specific flags, and missing quality inspection before a batch. Version 0.9.0 implements those improvements and updates dependencies without migrating every UI component to a new API. Windows x64 is the primary release target.

## Implemented

| Finding                                                                                        | Change                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Skipping setup or having an old `ffmpeg-checked` flag allowed encoding without FFmpeg.         | Encoding and preview now require a successful installation check. Skipping allows browsing the app; setup remains accessible from the encoder and Settings.                                                                                                                                                             |
| Setup checked FFmpeg but did not verify FFprobe.                                               | Both binaries are verified. Missing FFprobe produces an actionable error. Renamed custom FFmpeg binaries use a sibling named FFprobe.                                                                                                                                                                                   |
| Desktop launches can have a different PATH from terminals.                                     | Discovery includes Apple Silicon and Intel Homebrew locations, MacPorts, standard Linux locations, WinGet links and user package directories. A stale saved path falls back to discovery.                                                                                                                               |
| Installation required leaving the app and configuring PATH.                                    | A user-started installer uses WinGet on Windows or an existing Homebrew installation on macOS, streams logs, prevents duplicate installations, and verifies both tools afterward. Linux receives distribution-specific instructions.                                                                                    |
| The existing preview showed a command, not video quality.                                      | A separate Quality Preview encodes 1–30 seconds from a selected start time. It honors that file’s queue overrides and two-pass settings, uses temporary output, supports cancellation and embedded playback, and offers the actual encoded file to the system player. Changed settings mark a previous sample as stale. |
| Electron removed the `File.path` API used by drag-and-drop.                                    | Dropped paths now come from `webUtils.getPathForFile` through preload. Files without native paths are ignored; 3GP is accepted consistently. See [Electron’s supported API](https://www.electronjs.org/docs/latest/api/web-utils).                                                                                      |
| H.265 used FFmpeg’s generic pass options.                                                      | H.265 uses `-x265-params pass=…:stats=…` with escaped drive-letter colons. Pass statistics are isolated per job and removed after completion or failure. See [x265 multi-pass options](https://x265.readthedocs.io/en/master/cli.html#cmdoption-pass).                                                                  |
| Software presets were passed directly to NVENC.                                                | Presets map to NVENC’s p1–p7 values.                                                                                                                                                                                                                                                                                    |
| A build listing NVENC was treated as proof of compatible hardware.                             | Each listed H.264, HEVC, and AV1 NVENC encoder is tested with a one-frame encode. Unsupported codecs are hidden in the main settings and queue overrides. Saved hardware selections are preserved while capability checks are pending.                                                                                  |
| HEVC MP4/MOV output could be poorly recognized by Apple players.                               | HEVC encodes in those containers use the `hvc1` tag.                                                                                                                                                                                                                                                                    |
| Cancellation could start another pass or launch a job after asynchronous path preparation.     | Both transitions check cancellation. Batch controls stay locked until workers settle. Preview events do not change batch progress or logs.                                                                                                                                                                              |
| Old completed selections affected a new run’s progress.                                        | Progress counts only jobs included in the current session.                                                                                                                                                                                                                                                              |
| Duplicate IDs in imported queues could mix events from different jobs.                         | Imported IDs are made unique. Per-job retry counts are clamped.                                                                                                                                                                                                                                                         |
| CRF 0 was replaced with the default value.                                                     | Zero is preserved; quality values are bounded, including VP9’s 0–63 range.                                                                                                                                                                                                                                              |
| Storage quota errors could stop in-memory state updates.                                       | Persistence failures are handled inside the state updater.                                                                                                                                                                                                                                                              |
| Selected-folder read failures appeared as an empty queue.                                      | Root folder errors reach a visible message. Unreadable nested folders are still skipped.                                                                                                                                                                                                                                |
| Asynchronous log-file errors could crash the main process.                                     | Logging failures are handled and reported. Encoding can continue.                                                                                                                                                                                                                                                       |
| Closing the window left encoding processes running and could send events to destroyed windows. | Closing cancels jobs, triggers preview cleanup, and guards window updates.                                                                                                                                                                                                                                              |
| Preload exposed an unrestricted IPC invoke method.                                             | The renderer receives the specific app APIs and version information. Unexpected renderer navigation is blocked.                                                                                                                                                                                                         |
| Windows video seeking needs byte-range responses.                                              | Preview streaming now returns explicit HTTP 206 byte ranges, MIME types, lengths, suffix ranges, and HTTP 416 for unsatisfiable ranges. Native Windows embedded playback and seeking checks pass.                                                                                                                       |
| Drive-root and UNC outputs, file case, and reserved names caused Windows-specific failures.    | Source directories are joined in the main process, preserving drive/share roots. Queue deduplication ignores case and separator differences on Windows. Reserved device names and trailing dots are sanitized while preserving Unicode letters.                                                                         |
| Windows was not the primary packaging/CI target.                                               | Windows x64 NSIS packaging is explicit, runs the app as the current user, and offers an assisted per-user installation with a selectable folder. Windows CI checks actual encoding, discovery, embedded playback, and installer creation.                                                                               |
| macOS packaging referenced a missing entitlements file.                                        | Packaging uses Electron Builder’s defaults and the existing resources directory. macOS targets universal DMG/ZIP packages for Intel and Apple Silicon. Unused camera/microphone permission descriptions were removed.                                                                                                   |

The WinGet command targets the exact `Gyan.FFmpeg` package from the `winget` source, uses user scope, and retains the package manager’s integrity checks. Its manifest includes FFmpeg and FFprobe. Clicking Install accepts package/source terms, as described in the setup UI. See [Microsoft’s install options](https://learn.microsoft.com/en-us/windows/package-manager/winget/install) and the [package manifest](https://raw.githubusercontent.com/microsoft/winget-pkgs/master/manifests/g/Gyan/FFmpeg/8.0/Gyan.FFmpeg.installer.yaml).

Testing Library, SWC, type packages, formatting/lint tooling, and Electron Updater were also updated. The unused icon generator was removed. Node 22.12 or newer is required. A targeted `@electron/get → global-agent` override removes an obsolete vulnerable proxy dependency; clean dependency installation and Electron downloading succeeded with it.

HeroUI 3.2.6 was available during the audit. It requires changes to component composition, props, theme CSS, and providers. This pass uses the latest compatible v2 release; a v3 migration should include real component interaction and visual tests. [HeroUI’s migration guide](https://heroui.com/en/docs/react/migration/full-migration) documents the scope.

After updates, `npm audit --omit=dev` reports **zero vulnerabilities**. The full audit reports **20 moderate findings, zero high, zero critical**, tracing to the unpatched [`sprintf-js` precision denial-of-service advisory](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) in test/coverage tooling. The affected development packages are excluded from the packaged app. Automatically suggested downgrades of Jest/ts-jest were not applied.

## Validation

- 112 unit/regression tests pass, including installation, preview validation and cleanup, cancellation, queue import, and drag-and-drop.
- TypeScript checks and the production build pass.
- Linux x64 unpacked packaging succeeds with Electron 44.7.0.
- Real FFmpeg integration checks produce a 30.000-second H.264 preview, a 2.000-second H.265 two-pass sample, and a 2.008-second VP9 two-pass sample, all with audio. The VP9 difference is muxer/audio packet timing. The integration test exercises spaces and colon escaping in pass-statistics paths.
- The integration check is available as `npm run test:ffmpeg`, using PATH or `FFMPEG_PATH` / `FFPROBE_PATH`. Temporary test binaries were used for this audit; they are not added to app dependencies.
- Native Windows Node 26.7.0 with FFmpeg/FFprobe 9.0.2 and WinGet 1.29.380 passes actual encoding, renamed executable, Unicode path, and stale-PATH discovery checks. WinGet installation arguments and error paths are covered with process mocks; the existing Windows FFmpeg installation was not changed. macOS Homebrew and universal packaging still require native verification.
- The validation workflow checks dependency installation, lint, tests, and production builds on Linux, Windows, and macOS. Windows additionally verifies real encodes, executable discovery, embedded preview streaming/playback/cleanup/cancellation, and builds/uploads its NSIS installer. Linux runs real FFmpeg encoding checks. This workflow has not yet run on GitHub.
- The hidden native Windows Electron 44.7.0 smoke check passes preview generation, HTTP byte-range streaming, decoded H.264 playback with an advancing clock, seeking, cleanup, and cancellation with isolated temporary app data. It exposed and verified the fix for ignored Range headers. Broader visual/accessibility and system-player interaction checks remain necessary before release.
- Native Windows Electron Builder successfully creates the unsigned `dist/encode-all-0.9.0-setup.exe` installer. Linux cross-installer generation needs Wine, so the NSIS build was verified with Windows tooling.
- The full Jest suite was run on Linux. Running Jest directly through the WSL UNC share encountered a module-resolution limitation; the CI job checks a normal native Windows checkout.

## Prioritized follow-ups

| Priority | Improvement                                                                | Benefit / remaining issue                                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | Validate installer lifecycle and macOS releases                            | Exercise Windows install/uninstall, live WinGet installation, system-player fallback, code signing, and native macOS Homebrew/universal builds. Core Windows preview, encoding, paths, and installer creation are verified. |
| High     | Validate software encoders and copied streams against the target container | NVIDIA hardware codecs are now individually probed. Copying H.264 into WebM or incompatible subtitles into MP4 can still fail; profiles/queue overrides can bypass UI compatibility choices.                                |
| High     | Define failed-output and resume behavior                                   | Failed/canceled batch encodes can leave partial files. Unique output naming avoids overwrites but retries may leave additional partial outputs. Use explicit ownership tracking before deleting anything.                   |
| Medium   | Seek previews near a scene without decoding the entire preceding video     | The current output-side seek is accurate, but previews late in a long video may take time. Add verified input-side seeking with correct timestamp handling.                                                                 |
| Medium   | Side-by-side original/sample viewing and sample comparison history         | Make compression changes easier to evaluate. Retain the actual target-format sample for comparisons; offer compatible viewing without silently changing its encoding settings.                                              |
| Medium   | HeroUI v3 migration and lazy loading                                       | Modernize component APIs and theme styling. The current renderer JS is approximately 2.2 MB and CSS 300 KB before compression; defer queue/settings panels where practical.                                                 |
| Medium   | Apple VideoToolbox, Intel QSV, and AMD hardware encoders                   | Extend hardware support with codec-specific quality/preset handling and real capability probes.                                                                                                                             |
| Medium   | Disk-space estimates and batch preflight                                   | Catch missing inputs, unwritable outputs, insufficient space, unsupported codecs, and invalid profiles before launching a large batch.                                                                                      |
| Medium   | Queue validation on local-storage hydration and quieter persistence        | Imported files are sanitized, but stored state is trusted after JSON parsing. Persisting every progress/probe update also adds synchronous work for large queues.                                                           |
| Medium   | Notifications, pause/resume, and an explicit continue-on-error option      | Make long unattended batches easier to manage. Current behavior stops scheduling new jobs after retries are exhausted.                                                                                                      |
| Medium   | Subtitle conversion choices and output navigation                          | Unicode filenames and Windows device-name handling are fixed. Offer MP4 text-subtitle conversion and add open-folder/reveal-output actions to the summary.                                                                  |
| Low      | Wire up or remove Electron Updater                                         | The dependency is present but the app has no update-check flow.                                                                                                                                                             |

Normal preview release and window closure remove registered samples. Crashes or forced termination can leave temporary preview directories; a future startup cleanup policy should account for concurrent app instances and external players that still hold a file open.
